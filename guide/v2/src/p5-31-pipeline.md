# Конвейер агентов в производстве {#ch31 data-short="Глава 31. Конвейер агентов"}

Самая развёрнутая форма команды агентов работает на стороне разработки. Заявка проходит стадии от создания до релиза, агенты и люди работают через общее состояние заявки и не вызывают друг друга напрямую. Человек вмешивается в заранее названных точках. Глава описывает стадии, протокол агентов, правило «модель извлекает — код считает», обучение агентов без самообучения и наблюдаемость. Цифры в ней — из практики организации, где адаптировали методику [1].

Боковые состояния — спам, дубль, эскалация, срыв — не тупики. Терминальных состояний два: релиз и отмена. Дубли агенты не закрывают сами, они ставят метку.

Седьмое правило появилось после замера: 221 из 267 открытых задач в организации завели сами агенты. Находки агентов теперь фиксируются строками в отчёте, новые заявки из них не создаются.

### Модель извлекает, код считает

Любое число, которое влияет на решение, считает детерминированный код. Модель только извлекает факты по рубрике.

<table>
<thead><tr><th>Где</th><th>Что делает модель</th><th>Что делает код</th></tr></thead>
<tbody>
<tr><td>Приоритет заявки</td><td>Оценивает влияние, срочность, снижение риска и трудоёмкость по шкалам</td><td>Считает приоритет по формуле и порогам. Ошибки с потерей денег или данных идут в высший приоритет мимо формулы</td></tr>
<tr><td>Оценка трудоёмкости</td><td>Извлекает факты из требований</td><td>Считает оценку и надбавки за отсутствие критериев, зависимостей, контракта</td></tr>
<tr><td>Приёмка</td><td>Переводит шаги сценария в план проверки</td><td>Выносит вердикт: действие выполнено, ожидание совпало, улика собрана</td></tr>
<tr><td>Квартальная страница OKR</td><td>—</td><td>Строит страницу из данных: одинаковые данные дают байт в байт одинаковую страницу</td></tr>
</tbody>

Число, которого нет в фактах, чужой ключ задачи и устаревшие факты код отклоняет. Это то же правило, что для уверенности в главе 6: считает инструмент, а модель только приносит данные.

### Круг правок

Ревьюер размечает замечания как блокер, существенное или мелочь, при сомнении класс понижается. Агент выходит из круга правок по одному из трёх условий: нет блокеров и существенных замечаний; набор замечаний повторился — это петля; исчерпаны три круга. Правки ограничены файлами исходного изменения и 30% его объёма. Ожидание человека до 72 часов круги не расходует. Изменение с открытым блокером не вливается никогда.

### Обучение агентов без самообучения

<thead><tr><th>Элемент</th><th>Как устроено</th></tr></thead>

::: caption
Таблица 4. Управляемое улучшение агента

Базовая диагностика одного такого агента на 24 реальных замечаниях показала: из 19 предложенных им правок 17 были комментариями вместо изменений. Закрытые задачи он комментировал как живые, а два замечания к одной задаче давали противоречащие комментарии. Эталонный набор ловит именно такие слабости.

::: thesis
Машина не должна уметь менять то, чем её поправляют. Правила агента курирует человек и меняет через отдельное изменение. В свою память агент пишет, свои правила он не меняет. Петлю, которая оптимизирует сигнал без проверки человеком, не замыкают.
:::

### Наблюдаемость и регламент сбоя

Один экран показывает, всё ли работает, а если нет — что и с какого момента. На нём пульсы сервисов, доступность, ошибки, расход токенов и остаток квот. Агент или сервис без строки в реестре отмечается как «не наблюдается», и через 15 минут уходит алерт. Конфигурацию меняют только через репозиторий и слияние владельцем.

::: caption
Таблица 5. Регламент сбоя для людей и агентов
:::

Каждое новое звено конвейера проходит одну процедуру до строки кода: контекст, сравнение готовых решений с открытым кодом, решение с рассмотренными вариантами, последствия. С нуля пишут, только если подходящего готового решения нет. Готовность звена определяет сценарий «было — стало», который можно пройти руками.
