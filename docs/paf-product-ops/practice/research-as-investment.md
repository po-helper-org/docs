# Ценность информации: какую зависимость донасыщать первой

В [разделе 9](../theory/confidence-points.md) методологии есть правило слабого звена, но нет ответа на вопрос: **какую из слабых зависимостей донасыщать первой, если времени хватает не на все**. Репозиторий [`research-as-investment`](https://github.com/po-helper-org/research-as-investment) (MIT, методология и навык Claude Code для исследования идей) отвечает на него через ценность информации.

## Исследование как ставка

Исследование окупается тремя способами: решение; переиспользуемое знание; новые гипотезы. Исследование, брошенное на середине, не даёт ни одного. Правило глубины родственно «трём исходам гейта»: начатый уровень доводится до критерия завершения либо останавливается по критерию отсечения с записью причины; «бросили на середине» исхода не имеет.

## Чувствительность оценки

Для каждого критерия задаётся правдоподобный диапазон. Считается итоговая оценка в худшем и в лучшем случае.

- Лучший случай ниже порога — **отсечь** («не окупится», в архив с условием воскрешения).
- Худший случай выше порога — **идти к покупателю**.
- Иначе исследуются только критерии, чей диапазон переводит итог через порог, в порядке размаха; при равном размахе приоритет у того, что обычно не меряют («кто платит», канал).

Рубрика по умолчанию: порог 3,0; минимум по критерию 2; девять критериев; шесть стоп-критериев; потолок оценки, пока у критерия нет источника (например, «кто платит» не выше 3).

В терминах методологии это формализованный ответ на вопрос «какое слабое звено, чей диапазон пересекает порог гейта, донасыщать». В `poh-cortex` такого приоритизатора нет: есть только проверки «протухло», «стыки» и «пробелы».

## Шкала доказательств рынка E0–E6

| Уровень | Что это |
|---|---|
| E0 | Мнение модели без источника |
| E1 | Вторичный источник |
| E2 | Первичный источник (закон, отчётность) |
| E3 | Поведение рынка (раунды, вакансии, тендеры, прайсы) |
| E4 | Покупатель рассказал о прошлом поведении |
| E5 | Обязательство (время, репутация, интро к лицу, принимающему решение, письмо о намерениях) |
| E6 | Деньги (предоплата, оплаченный пилот) |

E0–E3 добываются поиском, E4–E6 — только разговором и продажей.

!!! warning "Две шкалы с разными объектами"
    Лестница CP ([приложение A](../appendix/ladder.md)) оценивает **исполнимость внутреннего обещания**, а шкала E — **спрос внешнего рынка**. Не «переводите» одну в другую: например, интервью E4 по потолку канала не выше ступени 3, хотя в шкале E оно сильнее документов E1–E3.

## Глубина исследования

| Уровень | Бюджет |
|---|---|
| L0 — скрининг | До 5 поисков, ~15 минут |
| L1 — кабинетная проверка | 15–30 поисков, 1–2 часа |
| L2 — досье | 40–80 поисков, полдня |
| L3 — покупатели | 5–15 разговоров, 1–2 недели; ключевые утверждения на E4+, хотя бы одно E5 |
| L4 — деньги | Пилот или предоплата, 1–3 месяца, E6 |

## Атомарная база знаний

Один факт — одна строка с источником, датой (`as_of`, `checked`), уровнем E и тегами; есть проверка устаревших фактов (старше 90 дней). Журнал окупаемости показывает, растёт ли доля переиспользования и падает ли стоимость решения (поисков на одно решение). Расхождение с Нексусом: у фактов нет владельца и частоты изменений.

## Зрелость

Прототип: один коммит, тесты проходят, база знаний пока пуста, заполнен только учебный пример (оценка в лучшем случае ниже порога, вердикт «отсечь»).

## Другие инструменты решений

- [`po-agent`](https://github.com/po-helper-org/po-agent) — консультант PO по решениям: 14-шаговый процесс (классификация и обратимость, связь с целью, главное неизвестное, минимум два варианта и «ничего не менять», разложение уверенности по измерениям, попытка опровергнуть, рекомендация с ценой, проверяемый следующий шаг, самопроверка). Режимы: Senior, Lead и ретроспектива без эффекта «знал бы заранее». Подтверждает правило слабого звена на уровне решения, а не ставки.
- Агент-исследователь с тормозами (эксперимент в `private-po-product`): порядок вопросов — протухшие узлы под ставками → недостающие доказательства → ценность информации → открытые вопросы → ~20% разведки; тормоза — дневной лимит токенов, потолки прогона, стоп при +50% бюджета, пауза при очереди больше 30 записей.
- **Реестр блокеров:** блокер — это работа, которая стоит и которую может снять только человек; строки «открытые» и «снятые», у каждой что стоит, кто нужен, что сделать. Это постоянный список для «запроса эскалации через отсутствующий артефакт» ([Шаг 6](../mechanics/step-6-dependencies.md)).
