# Доска задач ИИ-агентов и приёмка

В [П9](../playbook/p9-agent-team.md) методология говорит *что* делегировать агентам. Практика добавила *как ставить задачу и как принимать результат* — так, чтобы делегирование снимало нагрузку, а не создавало вторую очередь приёмки ([Шаг 3-тер](../mechanics/step-3-ter-morning-ritual.md)).

!!! abstract "Где реализовано"
    [`poh-widget-harness`](https://github.com/po-helper-org/poh-widget-harness) («PO-Harness»), ADR 0001–0002; [`poh-hermes-bridge`](https://github.com/po-helper-org/poh-hermes-bridge), ADR 0001–0004. Зрелость: в эксплуатации с 12 октября 2026.

## Доска

Все поручения агентам собираются в одном месте. Основа — встроенная доска Hermes Kanban (MIT): `triage → ready → running → blocked (нужен ответ) → review → done`, плюс `scheduled` для отложенных. Агенты PO-команд сами откладывают работу из чатов во «Входящие». Правила безопасного режима:

| Параметр | Значение | Смысл |
|---|---|---|
| В работу | Только по слову PO | Агент сам себе задачу не берёт |
| Параллельных исполнителей | 1, затем 3 по решению владельца | Лимиты подписки и качество приёмки |
| Автодекомпозиция | Выключена | Задачу делит человек |
| Автоматическая приёмка | Выключена | Принимает человек |

Агент-исполнитель — отдельный процесс **без контекста чата**: всё нужное лежит в теле задачи.

## Задача из шести строк

Агенту не ставят задачу без этих полей:

| Поле | Пример |
|---|---|
| Что | Черновик письма смежнику с запросом нового срока |
| Срок | Сегодня к 10:30 |
| Как проверим | В письме названа дата и что будет без неё |
| Что останется PO | Прочитать и отправить |
| Откуда | Какое обещание или заметка породили задачу |
| Сдача на приёмку | Что и где агент положит |

Плюс уровень автономии: **«молча» · «сделай и доложи» · «спроси до»**. Внешнее, необратимое и любая запись в знание — всегда «спроси до». Задача без «как проверим» превращает приёмку в переделку. Одну и ту же задачу, поставленную второй раз теми же словами, превращайте в постоянное правило агента или расписание.

## Приёмка

Агент **не закрывает задачу сам**: закрытая агентом помечается «без приёмки». Принимает человек: «Принять» или «Вернуть» с замечанием дословно (задача снова в очереди). Вопрос агента — один конкретный вопрос с вариантами. Разговор живёт в треде: одна задача — один тред; задачи из Инбокса идут по тихой подписке, чтобы не будить бота-диспетчера.

Это ручная форма питчинга доверия ([архитектура](../theory/architecture.md)): команда атакует аргументы, оценка назначается по выжившему доказательству.

## Перехват инициативы

Когда у агента Hermes кончились токены или нужна модель сильнее, владелец в Claude командует «продолжи задачу X». Четыре действия: взять задачу на стоянку (диспетчер не запустит исполнителя) → писать комментарий после каждого шага → сдать на приёмку с файлами → вернуть агенту. На время сдачи у задачи **снимается исполнитель**, иначе диспетчер успел бы запустить агента между «готово» и «на приёмке». Инициатор перехвата всегда человек; автоматического переключения нет.

Это даёт методологии недостающую роль: «старший исполнитель» (Claude) и «массовые исполнители» (Hermes), граница между ними — человек.

## «Штаб»: думает Claude, исполняет сервер

Через MCP-коннектор из приложения Claude (в том числе с телефона) доступны сами действия Hermes: доска, сессии, расписание, память и навыки, Jira и Confluence, сообщения от ботов, команды на сервере. Архитектура:

- OAuth 2.1 с коротким временем жизни доступа, вход через двухфакторный гейт, повторная проверка гейта сервисом;
- аннотации действий «только чтение» и «разрушающее», режим «спрашивать разрешение»;
- журнал каждого действия на запись;
- удаления и смена прав в Jira и Confluence закрыты программно, а не словами в инструкции;
- принятый риск, записанный в ADR: украденный токен коннектора равен доступу к серверу, смягчение — вход только через гейт и отзыв всех клиентов одной командой.

ADR моста честно фиксирует переход от текста к технике: сначала «технического шлюза записи нет — правило держится на скилле», затем аннотации и ограничения в коде.

## Открытый вопрос

Источник правды о задаче пока двойной: обещание лежит в Backlog.md, исполнение — в базе доски. Связь между ними вычисляется ([обещания](promises.md)), а вопрос единого источника остаётся открытым issue. См. [где практика расходится с методологией](gaps.md).
