# 8. Словарь PAF и связка с OKR

## Как корпоративный OKR ложится на термины PAF

| **Ваш уровень** | **Пример** | **Термин PAF** | **Кто это видит** |
| --- | --- | --- | --- |
| Objective квартала | Научить систему продавать чужие мероприятия | Цель из карты целей | Департамент, QBR |
| Key Result | Подключены 3 внешних организатора | Измеримое условие цели | Департамент, PMO |
| Ставка | Расчёты с внешним организатором работают | То, что должно быть правдой. Несёт порог, дату и CP | Только вы (и техлид при обсуждении даты) |
| Банч | Набор изменений, закрывающий ставку в этом спринте | Feature Bunch | Команда на планировании |
| Тикеты | Spike, разработка, тест против API | Задачи спринта | Команда, Jira |

**Что показывать на планировании:** банч и тикеты. Ставки и CP остаются вашим слоем — команда видит их в один момент, когда вы спрашиваете, под какую дату можно подписаться. На вопрос «а где фичи?» ответ прямой: вот банч под эту ставку.

**Оговорка про термин:** в оригинальной методологии ставка (Bet) — единица изменений стратегической линзы: запуск элемента портфеля или инвестиция в рычаг. В этой адаптации ставка играет роль условия достижимости KR. Термин сохранён ради связи с методологией, роль — адаптирована.

| **Понятие** | **Смысл** |
| --- | --- |
| Нексус | Живая модель объекта управления. Состоит из узлов знания с источником и датой |
| Кортекс | Операционная система работы с Нексусом через ИИ |
| Ставка (Bet) | В этой адаптации — обещание с порогом, датой и зависимостями: условие достижимости KR. В оригинальном PAF ставка — единица изменений стратегической линзы (запуск нового элемента портфеля или инвестиция в рычаг роста). Роль адаптирована, термин сохранён ради связи с методологией |
| Confidence Point | Уверенность в ставке. Ступень доказательства, не мнение |
| Лестница | Отображение «тип артефакта → ступень» |
| Гейт | Порог CP плюс дата. Ниже порога обещание не даётся |
| Bunch Window | Окно, в котором результат ещё создаёт ценность. Задаёт потребитель |
| Распад | Скорость устаревания знания: `effective_CP` = сила − распад(время × `change_rate`) |
| Карта целей (Goal Map) | Задаёт стратегическое направление и разделяет ответственность между командами без прямого вмешательства |
| Гэп | Разрыв между текущим продуктом и Видением. Задача инженера продукта — его сократить |
| Банч (Feature Bunch) | Набор фич, закрывающий гэп. Существует только в моменте; источник — анализ текущего состояния, а не стейкхолдеры |
| Размер банча | Ограничение объёма изменений: связан со скоростью восприятия изменений рынком, чтобы избежать перепроизводства |
| Рычаг (Lever) | Измеримое свойство бизнес-модели или продукта, инвестиции в которое увеличивают NPV |
| Бейл (Bale) | Инкремент продукта с понятным оффером и планом дистрибуции. По сути гипотеза спроса |
| Проращивание | Период, когда аудитория онбордится в фичу и формирует привычку |
| mNSM | Монетизируемая North Star Metric: конвертируемость ценности в прибыль по каждой фиче |
| Спелость контекста | Полнота плюс актуальность Нексуса. Два этапа жизни узла: созревание и увядание |

## Термины практики организации

| Понятие | Смысл |
| --- | --- |
| Обещание (PO) | Обязательство между людьми: заказчик, исполнитель, срок, источник-цитата. Две проекции — «я обещал» и «мне обещали». См. [практику](../practice/promises.md) |
| Хранитель | Роль или агент, который собирает артефакты и дожимает подтверждения; пишет только в очередь |
| Приёмка | Решение человека по результату агента: принять, вернуть с замечанием дословно. Ручная форма питчинга доверия |
| Срез | Явная пометка «данные до …, недоступно: …» вместо молчаливого пропуска или догадки |
| Гейт-диалог | Подтверждение записи с раундами вопросов, критиком и хэшем содержимого, а не единичное «да» |
| Уровень автономии | «Молча · сделай и доложи · спроси до» — поле поручения агенту |
| Эталон | Заранее размеченный случай для проверки поведения агента; набор эталонов — регресс на правилах |
| Недельный разбор | Регулярный анализ журнала агента, предложения правок знания — только после «да» владельца |
| Бюджет агента | Ограничения: лимиты подписки, время ответа, параллелизм, расход токенов |
