# Приложение E. Команды агента и инструмент `cortex`

В тексте методологии используются рабочие имена команд агента: `/paf-profile`, `/paf-rules`, `/paf-bet`, `/paf-cp`, `/paf-evidence`, `/paf-report`, `/paf-daily`, `/paf-pitch`, `/paf-equator`, `/paf-harvest`. В стартовом репозитории [`poh-cortex`](https://github.com/po-helper-org/poh-cortex) эти действия реализованы другим набором: навыки Claude Code (`.claude/skills/<имя>/SKILL.md`) и командная утилита `bin/cortex` на стандартной библиотеке Python.

!!! info "Команды и навыки"
    В Claude Code пользовательские команды объединены с навыками: файл `.claude/commands/x.md` и навык `.claude/skills/x/SKILL.md` создают одну и ту же команду `/x`. Новые команды рекомендуется оформлять как навыки; старый формат продолжает работать. См. [документацию Claude Code](https://code.claude.com/docs/en/skills).

## Соответствие

| Имя в методологии | В `poh-cortex` | Статус |
|---|---|---|
| `/paf-profile` | `cortex init` | Есть, как команда CLI |
| `/paf-rules` | Интервью лестницы, распада и гейтов из `ONBOARDING.md`; правит человек в `SCHEMA/` | Есть как инструкция, не как команда |
| `/paf-bet` | `/cortex-bet` | Есть |
| `/paf-cp` | `/cortex-bet`, раздел «Посчитать уверенность» | Есть внутри другого скилла |
| `/paf-evidence` | `/cortex-intake` | Есть |
| `/paf-report` | `/cortex-status` | Есть |
| `/paf-daily` | `cortex agenda` | Скилла нет, есть команда CLI |
| `/paf-pitch` | Абзац «оспаривание — новым артефактом» в `/cortex-bet` | Отдельной замены нет |
| `/paf-equator` | Абзац «Достижимость» в `/cortex-bet`, `cortex seams`, `cortex gaps` | Скилла нет, арифметики в коде нет |
| `/paf-harvest` | `cortex calibrate [--write]` | Скилла нет, есть команда CLI |

## Навыки

| Навык | Что делает |
|---|---|
| `/cortex-ask` | Спросить память по теме и ответить с якорями. Ответ заканчивается тремя строками: на чём держится · что неизвестно · что изменит ответ. Ничего не пишет |
| `/cortex-bet` | Завести или пересчитать ставку: порог, дата, зависимости. Достижимость — в трёх группах (сходится / под риском / не сходится); эскалация через отсутствующий артефакт; исход гейта. Обещание наружу даёт человек |
| `/cortex-intake` | Разобрать очередь `_intake/` в артефакты и узлы; затем пересчитать затронутые ставки «было / стало / основание» |
| `/cortex-status` | Отчёт руководителю из ставок: «Готово и проверено / Идёт по плану / Под риском (причина, нужно решение к дате, иначе снимаем дату)» без слов CP, репозиторий, Нексус |
| `/paf-gate` | Прогнать проверку целостности памяти и починить ошибки; чинить ослаблением схемы нельзя |
| `/paf-nexus-create` | Создать свой Нексус под объект управления |
| `/paf-node` | Создать или обновить узел с источником, ступенью, рёбрами |
| `/paf-okr` | Завести хребет OKR квартала: 2–4 цели, по 2–4 KR |
| `/paf-onboard` | Онбординг организации: документы и интервью → узлы со ступенью 2–3 и честными допущениями |
| `/paf-pulse` | Записать эпизод встречи, не обновляя узлы |

## Утилита `cortex`

Один файл на стандартной библиотеке Python; индекс строится при каждом запуске.

| Команда | Что делает | Пишет |
|---|---|---|
| `doctor` | Что загружено и не настроено (план интервью) | Нет |
| `gate [--all/--json]` | Проверка целостности памяти | Нет |
| `refresh [--dry-run]` | Пересчёт свежести и `effective_cp` | Да |
| `report` | Узлы, зоны, спелость по Нексусам | Нет |
| `ask "<тема>"` | Что память знает, с якорями | Нет |
| `context [--node/--kr/--scope]` | Контекст для агента в JSON | Нет |
| `who "<тема>"` | Кому писать | Нет |
| `stale [--soon]` | Очередь верификации протухшего | Нет |
| `gaps` | Знание, недостижимое от хребта целей | Нет |
| `agenda` | Пять минут в день: что требует внимания | Нет |
| `agents` / `profiles` | Агенты, зоны записи; профили PO | Нет |
| `intake list / route` | Очередь неразобранного | Нет |
| `node new / check / set` | Контракт записи узла | Да |
| `nexus list / add`, `schema show / init`, `init` | Объекты управления, схема, привязка | Да |
| `review [--accept/--reject]` | Приёмка черновиков агентов | Да |
| `resolve "<слово>"` | Упоминание → узел | Нет |
| `seams` | Стыки между PO: наружу и внутрь, по слабому звену | Нет |
| `pack [--all]` | Срез памяти под профиль | Да |
| `conflicts [--mark/--resolve]` | Расхождения между зонами, без выбора стороны | Да |
| `calibrate [--write]` | Итоги квартала: где были уверены, а не сработало | Да, с флагом |

Повысить `cp` командой `cortex node set --cp N` без нового `--source` инструмент отклоняет.

## Проверка качества

- **Гарантии** (`tests/acceptance.sh`): 11 проверок — четыре отказа, три расчёта, три проверки потолка обещания и арифметика цели.
- **«До Кортекса и после»** (`tests/comparison.sh`): шесть вопросов PO — успеем ли к дате; на чём держится цель; что уже неправда; откуда знание; кому писать; где переоценили себя.
- **Приёмка памяти раз в месяц:** три–семь ставок, у каждой `due` и `depends_on`; `stale` не старше двух сроков; очередь приёмки разбирается за неделю; есть хотя бы один стык наружу.
- **Тест качества агента:** разбор десяти записей; критерии — источник открывается, подтверждает именно это утверждение, ступень соответствует артефакту; порог девять из десяти. Контринтуитивный признак провала: агент ни разу не сказал «память не знает».

## Признаки мёртвой памяти

Много узлов с высокой ступенью и одинаковыми источниками; зелёная проверка при почти всех сиротах в `gaps`; за онбординг не прозвучало ни одного «не знаю»; очередь `_intake/` растёт неделями; `stale` показывает одно и то же; у всех узлов `change_rate: unknown`; калибровка ничего не поменяла.
