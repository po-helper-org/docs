# Приложение C. Сроки годности знания

Срок годности узла выводится из **частоты изменений объекта**, а не из типа Нексуса. Данных нет — `high`, не среднее: завысили — заплатили перепроверкой; занизили — получили протухшее знание и сорванный квартал.

| `change_rate` | `ttl_days` | Когда |
|---|---|---|
| high | 21 | Менялось чаще раза в месяц; узнаёте постфактум |
| medium | 42 | Менялось раз в квартал |
| low | 90 | Договоры, юридические основания, стабильные контракты |
| unknown | 21 | Данных нет ни у вас, ни у владельца; трактуется как high |

Откуда брать частоту — [раздел 9](../theory/confidence-points.md): измерить по истории (20 минут), спросить владельца, иначе `high`.

## Как считается распад

```text
p            = (сегодня − updated) / ttl_days
свежесть     : p < 0.5 — fresh · p < 1.0 — ripening · p ≥ 1.0 — wilting
потеря       = max(0, p − 1) × 2        # ступеней
effective_CP = max(2, cp − потеря)
```

До истечения полного срока ступень не теряется; за каждый «лишний» срок теряются две ступени; ниже ступени 2 не опускается. Пример: `cp` 6 при `p` = 3 даёт `effective_CP` = 2. Протухший узел автоматически снижает `effective_CP` ставок, которые на нём стоят (через слабое звено).

Спелость Нексуса = полнота × актуальность.

!!! warning "Подводные камни"
    - Если у узла нет поля `change_rate`, он берёт значение своего Нексуса, а не `high`. «Неизвестно = high» действует только для явно записанного `unknown`.
    - Запасные сроки по типам Нексуса (`_default` 90, `ops-model` 365 и т. д.) срабатывают, только когда `change_rate` не задан нигде. У базовых Нексусов он задан, поэтому «операционная модель живёт год» неверно: она живёт 90 дней, если у узла нет явного `ttl_days`.

## Калибровка распада

Срок годности пересматривается по наблюдаемой частоте изменений (история git). Пороги, чтобы не делать выводов из шума:

| Параметр | Значение | Зачем |
|---|---|---|
| Не считать после появления узла | 14 дней | Начальная правка — не частота |
| Минимум наблюдения | 45 дней | |
| Минимум изменений | 3 | «Две точки частотой не являются» |
| Минимум ставок на ступень | 3 | «Одна сорванная ставка ступень не порочит» |
| Не считать коммиты с маркерами | refresh, пересчёт, свежесть, chore, merge | Чистка — не изменение объекта |

Правку линейки делает человек отдельным коммитом ([Шаг 9](../mechanics/step-9-calibration.md)).
