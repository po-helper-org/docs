# Быстрый старт: создать память агента

Первый шаг нового проекта по методологии **Po-helper** — собрать **память агента**:
персонализированный набор данных, по которому AI-агенты ориентируются в репозиториях вашей
GitHub-организации, понимают, каким целям служит проект, и знают, как действовать.

Технически это **GROUND Vault** — граф **Нексусов** (структурированных узлов контекста) плюс
конфигурация **Кортекса** над ними. Наполняется поэтапно: каждый шаг добавляет полезный
контекст для управления организацией и принятия решений.

!!! abstract "Что вы получите на выходе"
    - `GROUND/config.yaml` — цифровой профиль: компания, продукт, роли команды, целевая фаза Кортекса.
    - **13 дефолтных Нексусов** (рынок / потребитель / продукт / система роста + операционные) — каркас, который агенты читают и пополняют.
    - Периметр организации в `.claude/domain-profile.md` — пути и репозитории, по которым агенты ориентируются.
    - Проверяемое качество памяти (валидатор + People Radar).

> **Правило порядка:** сначала **Нексус** (спелый контекст), потом **Кортекс**.
> Кортекс без контекста «усиливает мусор». Поэтому память собирается снизу вверх.

---

## Предпосылки

- **Claude Code** (CLI, desktop или IDE-расширение).
- Клон коробки po-helper: `git clone https://github.com/kibarik/po-helper.git`.
- Доступ к источникам контекста организации (репозитории GitHub, Confluence, документы) —
  понадобится на шагах наполнения.

---

## Шаг 1 — Установить экосистему

Разверните po-helper в проект. Из клона:

```bash
bash install.sh <путь-к-вашему-проекту>
# либо «сюда»:
bash install.sh
```

Или скиллом — попросите агента: **«Установи po-helper»** → запустится `/paf-install`
(копия коробки, CLI, адаптация конфигов, self-check, отчёт по MCP-серверам).

После установки — **Reload Window**, чтобы поднялись MCP-серверы (`ruflo` — память,
`serena` — код, `backlog`, `entire`). Проверьте отчёт: зелёное ядро + честно помеченные
опциональные пробелы.

!!! tip "Что установилось"
    `.claude/skills` (пайплайны `/okr-*`, `/bft-*`, `/sprint-*`, `/paf-*`),
    `.claude/commands`, каркас `GROUND/NEXUS/`, `sa_documentation/` (schema и словарь терминов).

---

## Шаг 2 — Указать периметр организации

Чтобы агенты ориентировались по репозиториям GitHub-организации и говорили на языке домена,
заполните `.claude/domain-profile.md` (из `.claude/domain-profile.template.md`):

- **пути и репозитории** организации, с которыми работают агенты;
- **доменные термины** и их значения;
- ландшафт внешних команд (если есть).

Это опорная карта: `/paf-init` и последующие скиллы используют её, чтобы связать память с
реальными артефактами организации.

---

## Шаг 3 — Создать скелет памяти

Запустите **`/paf-init`** — one-shot-настройку GROUND Vault. Скилл проведёт интервью
(по одному вопросу):

| Вопрос | Куда идёт |
|--------|-----------|
| Компания | `company` |
| Продукт: имя + `ascii-slug` + elevator pitch | `product.*` |
| Размер команды | `team.size` |
| **Кто Product Engineer?** (обязателен) | `team.roster.product_engineer` |
| Остальные роли (имя / `Cortex` / `null`) | `team.roster.*` |
| Целевая фаза Кортекса (1 / 2 / 3, по умолчанию 2) | `cortex.phase_target` |

На выходе — `config.yaml` и **13 Нексусов** как placeholder-узлы (Confidence Point 0.3,
`onboarded: todo`):

- **PAF-минимум:** `market`, `customer`, `product`, `growth`;
- **операционный:** `project-management` (delivery map PO);
- **intake→БФТ:** `problem`, `system-landscape`, `ownership`, `requester-domain`,
  `precedents`, `compliance`, `strategy`, `capacity`.

!!! warning "Readiness пока LOW"
    Нексусы созданы, но пустые (Context Ripeness ≈ 0). Это скелет памяти — наполнение впереди.

---

## Шаг 4 — Кастомные Нексусы под организацию

Дефолтного набора часто мало. Добавьте узлы под ваше решение — **`/paf-nexus-create`**:
интервью → новый `GROUND/NEXUS/<slug>/` + запись в `_registry.yaml`.

Типовые кастомные Нексусы: `sellers`, `buyers`, `team` (People Graph), `integrations`,
`compliance`, по-продуктовые. Так память отражает именно вашу организацию, а не абстрактный шаблон.

---

## Шаг 5 — Наполнить Кортекс контекстом

Ключевой этап ценности: превратить пустые Нексусы в живой контекст. Инструменты:

- **`/paf-onboard`** — оцифровка контекста клиента: ингест документов из `GROUND/_intake/`
  + интервью по `seed_questions` каждого Нексуса.
- **`/cindex`** (Confluence-индексатор) — обход пространств Confluence → атомарные узлы →
  роутинг в существующие Нексусы + граф `[[wiki-links]]` + навигационный MOC.
- **`/people-links`** — описать отношения PO с людьми → наполнить People Graph Нексуса `team`
  (кольца близости, кто по каким вопросам приходит, кто согласует).

Наполняйте **поэтапно**: каждый прогон повышает Context Ripeness Нексусов — и качество решений,
которые агенты принимают на этой памяти.

---

## Шаг 6 — Проверить качество памяти

Память полезна ровно настолько, насколько ей можно доверять. Проверка:

```bash
python3 sa_documentation/validate_ground.py GROUND   # ожидается OK
```

- **`/radar-calibrate`** (People Radar) — задаёт ситуационные вопросы, отвечает из Нексуса,
  вы сверяете с реальностью; при расхождении выдаёт correction-Prompt. Цикл до 10/10.

Если валидатор ругается (невалидный `slug`, пустой `product_engineer`) — исправьте и перезапустите.

---

## Что дальше

Память готова — Кортекс может работать. Запускайте первый пайплайн:

- **`/okr-planner`** — квартальные OKR из стратегического контекста.
- **`/bft-fast`** / **`/bft-writer`** — бизнес-функциональные требования.
- **`/sprint-planner`** — roadmap и план спринта.
- **`/request-intake`** — обработка внешних запросов → БФТ.

Каждый пайплайн читает и пополняет ту же память — контекст растёт с каждым циклом.

---

## Как устроена память (кратко)

| Слой | Что это | Роль |
|------|---------|------|
| **Нексус** | Граф структурированных узлов контекста (рынок, потребитель, продукт, люди…) | «Живой цифровой профиль», не статичный документ |
| **Кортекс** | Агенты + RAG по Нексусам + промпты + интеграции | «Проводник»: инженер работает через него, не вручную |
| **Context Ripeness** | Метрика спелости контекста (полнота × свежесть) | Гейт: пустой Нексус → решения на нём ненадёжны |
