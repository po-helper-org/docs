# Быстрый старт: создать память агента

Первый шаг нового проекта по методологии **Po-helper** — собрать **память агента**: проверяемый
контекст, по которому ИИ-агенты ориентируются в вашей организации, понимают, каким целям служит работа,
и знают, чему в ней можно верить.

Технически это **Кортекс** — репозиторий [`poh-cortex`](https://github.com/po-helper-org/poh-cortex):
Markdown под git, один инструмент `bin/cortex` на стандартной библиотеке Python, схема правил как данные.
Ни базы, ни сервисов, ни зависимостей. Устройство памяти — в разделе
[PAF Product Ops](paf-product-ops/index.md).

!!! abstract "Что вы получите на выходе"
    - `GROUND/config.yaml` — цифровой профиль: организация, продукт, продуктовый инженер.
    - Откалиброванные правила измерения в `GROUND/SCHEMA/`: лестница доказательств 2–9, сроки годности знания, гейты.
    - Профили PO и куратор ядра.
    - Нексусы под ваши объекты управления — те, из-за незнания которых уже принимали плохие решения.
    - Цели квартала и ставки с порогом и датой.

> **Правило порядка:** сначала **Нексус** (спелый контекст), потом **Кортекс**.
> Агент без проверяемого контекста «усиливает мусор», поэтому память собирается снизу вверх.

---

## Предпосылки

- `python3` — ничего ставить не нужно.
- ИИ-агент, который умеет читать репозиторий (например, Claude Code). Любому агенту хватает файлов
  `ONBOARDING.md` и `AGENTS.md`: они не зависят от конкретного инструмента.
- Один-два часа для настройки; она делается один раз за квартал.

---

## Шаг 1. Склонировать и проверить — минута

```bash
git clone https://github.com/po-helper-org/poh-cortex my-cortex
cd my-cortex
bin/cortex doctor
```

Ответ будет списком того, что не настроено: пустой `config.yaml`, профили-образцы, не назначен куратор ядра,
лестница не откалибрована, гейты не заданы, нет целей квартала. **Это не ошибки, а ваш план.** Репозиторий
приезжает пустым намеренно: методология внутри, контекст организации — нет, и заполнить его за вас нельзя.

## Шаг 2. Настройка — разговор с агентом

Откройте папку в своём ИИ-агенте и скажите одну фразу:

> Прочитай ONBOARDING.md и проведи меня по настройке Кортекса.

Агент задаёт вопросы **по одному** и по ответам заполняет конфигурацию. Он спросит:

| О чём | Зачем это нужно |
|---|---|
| Организация, продукт, его идея | К чему привязана память |
| Кто принимает продуктовые решения и по каким объектам | Зоны и профили PO |
| Кто один отвечает за общее знание | Куратор ядра: без него протухшее ничьё |
| Чем в вашем контуре подтверждается каждая ступень | [Лестница доказательств](paf-product-ops/appendix/ladder.md) |
| Как часто менялся каждый тип объекта за полгода | [Сроки годности знания](paf-product-ops/appendix/decay.md) |
| Какие обещания уходят за пределы команды и под какое доказательство | [Гейты](paf-product-ops/appendix/gates.md) |
| О каких объектах вы регулярно принимаете решения | Состав Нексусов |

**Разделение ролей:** агент спрашивает, считает и готовит черновики; вы отвечаете, принимаете или отклоняете.
«Не знаю» — валидный ответ: пустой раздел честнее выдуманного. Файлы правил в `GROUND/SCHEMA/` агент
**сам не правит** — он показывает готовый блок, вы вставляете его или принимаете отдельным PR: кто правит линейку,
тот получает любое число. Единственное, что нельзя пройти в одиночку, — гейты: «что считается обещанием наружу»
знает руководитель, на разговор с ним хватает 15 минут.

## Шаг 3. Наполнение — тем же разговором

> Проведи онбординг: давай по одному Нексусу.

Агент идёт по объектам управления, задаёт вопросы из шаблонов и на каждый ответ заводит узел с источником
и честной ступенью уверенности. Всё, что он пишет, остаётся черновиком, пока вы не приняли:

```bash
bin/cortex review                                 # что он собрал
bin/cortex review --nexus <объект> --accept-all   # принять пачкой
bin/cortex review --accept <узел>                 # принять поштучно
```

Наполнение делается не за присест: один Нексус за подход, по мере того как контекст становится нужен для решений.
Правило меры: узел и Нексус заводятся тогда, когда из-за их незнания уже принимали плохое решение. Три–четыре Нексуса —
нормально; восемь на старте означают, что вы собираете справочник вместо управления
([уровни зрелости](paf-product-ops/theory/maturity-levels.md)).

---

## Что получится

Память, из которой агент отвечает **с якорями**, а не по общим соображениям:

```bash
bin/cortex ask "<тема>"        # что известно, чем подтверждено, что неизвестно
bin/cortex who "<тема>"        # кому писать по этому вопросу
bin/cortex agenda              # пять минут в день: что требует внимания
bin/cortex calibrate           # конец квартала: где были уверены, а не сработало
```

Ни одно утверждение в этой памяти не существует без источника, а уверенность нельзя поднять рассуждением —
только новым артефактом. Полный перечень команд — в [приложении E](paf-product-ops/appendix/commands.md),
структура файлов — в [приложении D](paf-product-ops/appendix/files.md).
